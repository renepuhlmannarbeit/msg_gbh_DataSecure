## P1 — Über-Redaktion: Komma- und Partikel-Namen umgehen `looksName()`

**Priorität: hoch.** Das ist ein Regress gegen einen bereits behobenen Fehler.

**Ort:** `plugins/data-secure/server/privacy/entities.js`, Funktion
`collectHeaderNameCandidates()`, Zeilen 130–137.

Beide neuen Zweige pushen direkt in das Ergebnis und überspringen damit
`looksName()` — also die Prüfung gegen `ROLE_WORDS` und `TECH_TERMS`:

```js
if (commaName.test(s)) {
  out.push({ value: s, confidence: 'header_comma', noSurnameAlias: true });
  continue;
}
if (particleName.test(s)) {
  out.push({ value: s, confidence: 'header_particle' });
  continue;
}
```

**Reproduktion** (Profil `personnel_profile`, Zeilen bewusst *keine*
Markdown-Listenpunkte):

| Eingabezeile | Ist | Soll |
|---|---|---|
| `Logistik, Gesundheitswesen` | `[PERSON_001]` | unverändert |
| `Scrum, SAFe` | `[PERSON_002]` | unverändert |
| `Versicherung, Krankenkassen` (`applicant`) | `[PERSON_001]` | unverändert |
| `Deutsch, Englisch` (`applicant`) | `[PERSON_002]` | unverändert |

Branchen, Sprachen und Methoden werden zu Personen. Dieselbe Klasse wie der
bereits behobene Fehler „User Stories → [PERSON_004]". Das Golden-File deckt es
nicht auf, weil dort alle Aufzählungen Listenpunkte sind, die
`isStructuralLine()` ohnehin filtert.

**Zu tun:**

1. Beide Zweige durch dieselbe Prüfung schleusen wie der `bigram`-Zweig. Bei
   `commaName` die Prüfung auf die Namensbestandteile *ohne* Komma anwenden,
   also `looksName(titleCase(s.replace(',', ' ')))` oder gleichwertig — das
   Komma darf die Tokenzählung nicht verfälschen.
2. `noSurnameAlias: true` bei `commaName` beibehalten. Das ist richtig: bei
   `Mustermann, Max` ist das *erste* Token der Nachname, nicht das letzte, und
   ein Alias auf das letzte Token wäre falsch.
3. Erwägen, bei `commaName` zusätzlich den Nachnamen-Alias auf das **erste**
   Token zu setzen, damit ein späteres bloßes `Mustermann` im Text ebenfalls
   ersetzt wird. Wenn das zu unsicher erscheint: nicht machen und stattdessen
   einen Kommentar hinterlassen, warum.

**Tests:** in `tests/test-pii-regression.js` ergänzen —

- `Logistik, Gesundheitswesen`, `Scrum, SAFe`, `Deutsch, Englisch` und
  `Versicherung, Krankenkassen` bleiben in `personnel_profile` bzw. `applicant`
  als Klartextzeile erhalten und erzeugen **keinen** `PERSON`-Platzhalter
  (`counts.PERSON === 0`).
- `Mustermann, Max` wird weiterhin zu `[PERSON_001]`.
- `von der Heide` bzw. `Anna von der Heide` wird weiterhin erkannt.
- Ein Fall, der belegt, dass `Product Owner, Scrum Master` als Rollenzeile
  erhalten bleibt.

## P2 — Doku widerspricht dem Code: Unabhängigkeit des Residual-Gates

**Priorität: mittel.** Kein Fehlverhalten, aber eine falsche Zusage in einem
Sicherheitsdokument.

**Ort:** `docs/PLUGIN_SECURITY_MODEL.md`, Abschnitt „Two independent checks, not
one", Zeilen 62–71, gegen `plugins/data-secure/server/privacy/engine.js`
Zeile 258.

`scanResidual()` verwendet jetzt `collectPersonSeeds(clean, profile)` — denselben
Kollektor wie der Redakteur. Die Doku behauptet weiterhin: *„The verifier must
not share them, or it can only ever confirm the redactor's own blind spots."*

**Bewertung:** Der Code soll so bleiben. Ich habe die Konvergenz gemessen —
Golden-Fixture, Kontaktblock, Komma-Zeilen und Vertrag brauchen alle genau
**einen** Pass, und der Recall des Gates ist besser als vorher. Falsch ist nur
die Doku.

**Zu tun:**

1. Den Abschnitt so umschreiben, dass er beschreibt, was tatsächlich passiert:
   der Gate prüft (a) Muster für direkte Identifikatoren und (b) dass kein
   Literal aus dem Dictionary des Redakteurs überlebt hat. Punkt (b) ist die
   nicht-zirkuläre Prüfung und trägt die Aussage — Punkt (a) teilt inzwischen
   die Personenheuristik mit dem Redakteur.
2. Ausdrücklich benennen, was daraus folgt: eine Person, die der Kollektor
   grundsätzlich nicht erkennt, findet auch der Gate nicht. Das ist die
   verbleibende Lücke, und sie soll dort stehen, statt durch eine
   Unabhängigkeitsbehauptung verdeckt zu werden.
3. Einen Test ergänzen, der die Konvergenz absichert: für die vier oben
   genannten Dokumentformen muss `anonymizeMarkdown()` mit `passes === 1`
   zurückkommen. Damit fällt auf, wenn eine künftige Änderung den Gate in eine
   Endlosschleife bis `MAX_PASSES` treibt.

## P3 — Beträge und Mengen werden als Postanschrift geschwärzt

**Priorität: mittel.** Vorbestehender Fehler, durch das neue `i`-Flag ausgeweitet.

**Ort:** `plugins/data-secure/server/privacy/base.js`, `POSTAL_ADDRESS_RE`
ab Zeile 89.

**Reproduktion:**

| Eingabe | Treffer |
|---|---|
| `Rechnungsbetrag: 50000 Euro netto` | `50000 Euro netto` |
| `Menge 10000 Stueck geliefert` | `10000 Stueck geliefert` |
| `Wert 12345 Punkte` | `12345 Punkte` |

Alle drei werden zu `[LOCATION_REDACTED]`. Vor dem Commit endete der Treffer
nach `50000 Euro`; das neue `i`-Flag zieht jetzt zusätzlich kleingeschriebene
Folgewörter mit hinein.

**Zu tun:** Das Muster darf nicht auf eine Zahl gefolgt von einer Einheit oder
Währung greifen. Bevorzugt als Ausschlussprüfung im `accept` des Detektors in
`structured.js`, nicht durch weitere Verschachtelung im Regex — die Lesbarkeit
des Musters ist schon jetzt am Limit. Auszuschließen mindestens: `Euro`, `EUR`,
`Stück`/`Stueck`, `Punkte`, `Stunden`, `Tage`, `Monate`, `Jahre`, `Prozent`,
`Einwohner`, `Exemplare`, `Teile`, `kg`, `km`, `qm`, `m²`, `Liter`.

Prüfen und im Test festhalten, dass echte Anschriften weiterhin greifen:
`20457 Hamburg`, `80331 München`, `04103 Leipzig Mitte`, sowie ein
kleingeschriebener Ortsname, wenn das mit dem `i`-Flag beabsichtigt war.

## P5 — Restfenster im neuen Publish-Ablauf benennen

**Priorität: niedrig.**

**Ort:** `plugins/data-secure/server/gateway/orchestrator.js`, der Abschnitt um
`moveSource(...)` / `publishPackage(...)`.

Die Quelldatei wandert nach `Processed`, **bevor** das Paket sichtbar wird. Ein
abfangbarer Fehler legt sie über `restoreProcessed()` zurück — ein harter
Prozessabbruch genau in diesem Fenster nicht. Dann liegt die Eingabe in
`Processed`, ohne dass ein Paket existiert, und der Anwender muss sie dort
herausfischen.

Das Fenster ist klein und der Entwurf insgesamt besser als vorher. Es soll aber
benannt sein:

1. Ein Satz in `docs/PLUGIN_SECURITY_MODEL.md` beim Publish-Ablauf.
