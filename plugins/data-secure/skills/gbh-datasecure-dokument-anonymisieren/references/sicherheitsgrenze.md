# Sicherheitsgrenze

Der lokale MCP-Server verarbeitet die Dateien tatsächlich. Skills liefern Routing- und Governance-Anweisungen, können aber nicht garantieren, dass bereits in eine Claude-Unterhaltung hochgeladene oder eingefügte Inhalte vom Modell ungesehen blieben. Für eine Datenschutzverarbeitung vor dem Modell müssen Quelldateien ausschließlich über den lokalen Betriebssystem-Mehrfachpicker eingehen. Einen technischen Eingangsordner gibt es nicht mehr.

Die lokale Grenze besteht nur in einer Claude-Desktop-/Cowork-Sitzung, in der `data-secure-local` tatsächlich verbunden ist. Cloud-Cowork, Web, Mobil und geplante Cloud-Aufgaben dürfen keine Originale erhalten; ein sichtbarer Skill oder Plugin-Eintrag beweist keine lokale Ausführung.

Auch Desktop-Cowork kann cloud-gehostet sein. Ein lokaler Dateizugriff aus einer
Cloud-Sitzung ist keine Freigabe dieses DataSecure-Pilots. Prüfe keine Originale über
Computer-Use, allgemeine Dateisystemwerkzeuge oder andere Connectoren. Der lokale Picker
ist der einzige Eingang; ein fehlendes Diagnosewerkzeug im Normalmodus ist dagegen
erwartet und kein Nachweis eines fehlenden lokalen MCP. Zur Installation kann der
Anwender „Dateien anonymisieren“ auslösen und den sichtbaren lokalen Picker abbrechen.
